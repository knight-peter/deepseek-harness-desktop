# dsh-desktop 使用总结

dsh-desktop 是 DeepSeek Harness（dsh）的桌面版：窗口里是原版 `dsh web` 界面，引擎作为子进程随应用启动/关闭。**无需安装 Node 或 pnpm**——运行时由应用自带（Electron 内嵌 Node）。

所有数据（会话、设置、凭据、插件）都在 `$DSH_HOME`（默认 `~/.dsh`），与命令行 `dsh` 完全共享：两边看到的是同一份数据。

## 1. 安装

### macOS

**推荐：一键安装脚本**（自动识别 Apple Silicon / Intel，下载对应架构包 → 去除隔离标记 → 装到「应用程序」→ 启动）：

```sh
# 安装最新版
curl -fsSL https://raw.githubusercontent.com/knight-peter/deepseek-harness-desktop/main/scripts/install-mac.sh | bash
# 指定版本（可选）：... | bash -s 0.1.1
```

**手动安装**（到 GitHub Releases 下载 `dsh-desktop-<版本>-arm64.dmg`（Apple Silicon）或 `-x64.dmg`（Intel））：

1. 打开 dmg，把 `dsh-desktop` 拖进「应用程序」；
2. 首次打开若提示「无法验证开发者」（当前为 ad-hoc 签名、未公证，Gatekeeper 会拦第一次）：在 Finder 里**右键应用 → 打开**，确认即可；或执行 `xattr -cr /Applications/dsh-desktop.app`（一键脚本已自动处理，不会出现此提示）；
3. 打开后若系统询问是否允许本地网络连接，允许（引擎在 `127.0.0.1` 随机端口提供本地服务）。

### Windows / Linux

用对应平台的安装包（Windows 的 NSIS 安装器 / Linux 的 AppImage，由 CI 构建产出），安装/解压后同样直接运行。

## 2. 第一次启动

1. 打开应用，窗口先显示状态壳「引擎启动中…」（引擎 boot 约几秒）；
2. 就绪后自动加载完整界面——**原版 dsh web 的全部功能**（对话、工具、设置等）；
3. 引擎端口是随机分配的（不与 dsh CLI 默认的 3080 冲突）；
4. 关闭窗口即退出应用并停止引擎，无残留进程。

## 3. 界面速览

- **主窗口**：原版 dsh web 界面，用起来和浏览器里一样。
- **管理窗口**：主窗口右上角「管理」按钮，或菜单「窗口 → 管理窗口」（快捷键 `Cmd/Ctrl + ,`），三个页签（页签名：插件管理 / 设置与更新 / 开发调试）：
  - **插件管理**：已安装插件列表、安装/卸载/更新、版本列「最新 / 可更新 → 版本号」与放行提示；**作用于“全部已装插件”的操作（刷新 / 检查更新 / 全部更新）单独放在表格标题栏右侧**，下方输入行只管“安装一个插件”，两者分开不混淆；
  - **设置与更新**：应用更新（启动自动检查、更新源、手动「检查应用更新」）＋ 引擎版本与更新（检查/备份/应用更新，均有进度与结果反馈）；
  - **开发调试**：开发向功能合集（页签顶部 `?` 为总帮助）——新建插件脚手架、开发模式引擎来源、引擎调试端口（NODE_OPTIONS=--inspect）、引擎日志、配置树与 diff、补丁编辑器。
- 常用菜单：`Cmd/Ctrl + R` 重新加载引擎；`Cmd/Ctrl + Q` 退出。

## 4. 安装 dsh 插件

插件是扩展 dsh 能力的 npm 包（新工具、新服务、UI 组件等）。在**管理窗口 → 插件管理**：

| 来源 | 操作 | 说明 |
|---|---|---|
| **npm 包** | 选「npm 包」，输入包名（可带 `@版本`）→ 安装 | 底层由 `dsh plugin` 完成安装与分层，装完自动重启引擎 |
| **本地目录** | 选「本地目录」，填插件源码的**绝对路径** → 安装 | `file:` 链接；改代码后重启引擎即生效（适合自己开发插件） |
| **git 仓库** | 选「git」，粘贴 `git+https://…` → 安装 | 若提示 pnpm 拦截 prepare 脚本，按提示在 profile 的 `pnpm-workspace.yaml` 配 `allowBuilds` |
| **新建插件** | 输入插件名（小写字母/数字/连字符）→ 「新建插件」 | 生成模板到 `~/.dsh/plugins-local/<名字>/` 并自动安装——零基础起步的插件开发入口 |

- **卸载 / 更新**：列表里对应按钮；装、卸、更新后引擎自动重启（几秒），无需手动操作。
- **装 npm 包被 pnpm 拦构建脚本（如 node-pty）**：安装失败、或成功但提示「构建脚本未执行」时，界面会给出**「放行并重装」**——一键把 `allowBuilds` 写进 profile 的 `pnpm-workspace.yaml` 并自动重装（等价官方 `pnpm approve-builds --all` + 重跑）。git 依赖被拦 prepare 脚本同样处理。
- **安装过程实时可见**：pnpm 输出实时显示在插件页；失败会分类提示（包不存在 404 / 网络 / pnpm 缺失），并可一键「打开 profile 目录」查看。
- **检查更新 / 全部更新**：在插件表格标题栏右侧（**作用于全部已装插件**，与“安装单个插件”的输入行分开）。「检查更新」对比 npm registry 最新版。能查到最新版的插件，**版本列会显示「最新」或「可更新 → 版本号」**；**只有确有可更新版本时才会出现「更新到 版本号」按钮**（本地目录 / git / 离线查不到的只显示版本，无更新按钮）；「全部更新」按钮会实时显示可更新数量，如「全部更新（2）」。
- **操作反馈（顶部居中、穿透式轻提示）**：检查更新 / 全部更新 / 安装 / 卸载等操作的结果以**窗口顶部居中的 toast** 反馈——**同一时间只显示一条**（新提示替换旧提示），按成功 / 警告 / 失败着色、**半透明**，且**完全穿透鼠标（pointer-events: none）**：即使提示恰好浮在按钮上方也不挡点击、不挡视线，ok/info 约 3 秒、warn/err 约 5–6 秒自动淡出；进行中的操作显示带转圈的提示条。多行完整输出（逐包安装摘要、pnpm 报错等）始终保留在页面底部「操作日志」，不再占用插件页正文、也不会残留不清。
- **启动自动检查**：应用每次启动会在后台对已装的 registry 插件做一次版本检查（4 秒后执行），结果直接体现在插件页的版本列（「最新」/「可更新 → 版本号」）与更新按钮上，无需手动操作。
- **安装帮助**：安装输入行右侧的「?」按钮可展开/收起《安装帮助内容》（三种来源怎么填、类型列含义、常见问题）。
- **类型列含义**：`bundle` = 分层补丁插件（装完自动进 bundles 层生效）；`客户端` = 带 web UI 半的插件；`依赖` = 未声明 `dsh.bundle` 的普通包——**不会挂载为插件层**（安装完成也会给出提示）。
- 插件与你的电脑同权限（运行在引擎进程内）——**只安装可信来源的插件**。
- 想自己写插件：见 **[`dsh插件开发.md`](dsh插件开发.md)**（开发、测试、调试全流程）。
- **Windows 说明**：插件安装/卸载/更新在后台执行（隐藏控制台），不会弹出 cmd 窗口。

## 5. 更新功能

两类更新互不影响：**引擎更新**升级 dsh 本体，**应用更新**升级这个壳。

### 5.1 引擎更新（dsh 本体）

管理窗口 → 设置与更新 → **引擎更新**：

1. 启动时自动检查 npm registry 上的最新版本（无需设置）；「检查更新」可手动刷新；
2. 确认有新版本后本节才会出现「应用引擎更新」按钮；更新前建议**先「备份 $DSH_HOME」**——备份到 `~/.dsh-backup-<时间戳>`，出问题可整体还原（dsh 处于预发布期，数据格式不承诺兼容）；
3. 点「应用引擎更新」→ 重装引擎 → 自动重启。

更新只替换引擎程序，`~/.dsh` 里的会话、设置、凭据、插件全部保留。

### 5.2 应用更新（壳本身）

- 菜单 **dsh-desktop → 检查应用更新…**（仅发布版显示；GitHub Releases + GitCode 国内镜像双源，自动选可达源，需联网）；
- **启动自动检查（发布版，无需勾选设置）**：每次启动后台自动检查，有新版本即自动下载；
- **更新体验**：设置与更新页签 →「应用更新」区实时显示状态（已是最新 / 发现新版本下载中 / 下载完成），下载完成后才出现「重启并安装」按钮；弹窗提示「立即重启 / 稍后」——点「立即重启」自动更新并重启，点「稍后」则在下次退出应用时自动安装。手动「检查更新」会明确提示「发现新版本」或「已是最新版本」。

## 6. 常用设置（管理窗口 → 设置与更新）

| 设置项 | 说明 |
|---|---|
| 开发模式 checkout 路径 | 仅开发版生效：指向 deepseek-harness 源码目录，用它构建的 CLI 当引擎（已移至「开发调试」页签） |
| 引擎调试端口 | 高级：给引擎开 `--inspect`，用 Chrome DevTools（`chrome://inspect`）断点调试（已移至「开发调试」页签） |

> 引擎更新与应用更新的**启动自动检查**无需配置：发布版每次启动后台自动执行；确认有新版本后，管理窗口「引擎更新 / 应用更新」区才会显示对应的更新按钮。

## 7. 故障排查

| 现象 | 处理 |
|---|---|
| 首次打开被 Gatekeeper 拦 | 右键 → 打开；或 `xattr -cr /Applications/dsh-desktop.app`；或用一键安装脚本（自动处理） |
| 窗口停在「待机 / 未找到 dsh 引擎」 | 开发版需先 `pnpm run install-engine`（见仓库 README）；发布版确认应用内 `Resources/engine` 存在 |
| 引擎启动失败，错误卡片指名插件 | 该插件未安装 / 包名错误 / 版本不兼容：卸载或修正后重启引擎（壳不会自动重启，防崩溃死循环） |
| 页面白屏 | 健康检查断言 `__DSH_BOOT__`，连错服务会报错而非白屏；确认没有旧实例占用端口 |
| 别处复制的内容粘贴不进 dsh（macOS 上 Cmd+C/V 失效） | 应用菜单缺少「编辑」菜单会导致 macOS 上复制/粘贴快捷键整体失效。0.1.x 起已内置编辑菜单；若仍异常，可用菜单「编辑 → 粘贴剪切板内容到输入框」兜底（不依赖页面自身的粘贴处理） |
| 装 git 插件失败 | pnpm ≥ 10 拦 prepare 脚本：按提示在 profile 的 `pnpm-workspace.yaml` 配 `allowBuilds`，或直接在插件页点「放行并重装」 |
| 装 npm 插件失败 / 提示 Ignored build scripts | pnpm ≥ 10 默认不执行依赖构建脚本（pnpm 11 strict 会直接失败）：插件页点「放行并重装」即可（自动写 allowBuilds 并重跑安装） |
| Windows 上对话时 agent 执行命令、或安装/更新插件、更新引擎时弹出 cmd 窗口 | 旧版本打包版的行为：命令在前台 cmd 窗口执行（有时执行完窗口不关）。新版已修复——命令改为在隐藏控制台后台执行，不再弹出窗口（对话时 agent 跑命令也一样）；仍弹窗说明是旧版本，请先更新应用 |
| 想断点调试引擎 | 设置 → 引擎调试端口 → Chrome DevTools attach |
| 日志在哪看 | 管理窗口 → 调试工具（实时流 + 最近 500 行回放，可清空/导出） |
| 想直接看数据目录 | 菜单「帮助 → 打开引擎数据目录（$DSH_HOME）」 |

## 8. 卸载

- 把 `dsh-desktop.app` 拖进废纸篓即可——应用无后台服务、无残留进程。
- `~/.dsh` 是你的数据（会话/设置/凭据/插件），卸载**不会**删除它；如需彻底清理，手动删除 `~/.dsh` 以及 `~/Library/Application Support/dsh-desktop`（壳的设置文件）。
