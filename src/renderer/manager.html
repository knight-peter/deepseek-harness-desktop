包名版本类型操作
安装帮助内容 —— 三种来源怎么填：
· npm 包：直接填 npm 包名，可带版本，如 dsh-better-sidebar 或 dsh-better-sidebar@latest（发布到 npm registry 的插件，安装/更新都会做版本检查）
· 本地目录：填插件源码的绝对路径，如 /Users/you/projects/my-plugin（按 file: 链接安装；改代码后重启引擎即生效，适合自己开发的插件）
· git 仓库：粘贴 git+https://github.com/owner/repo.git（可带 #tag 指定版本）
装完看类型列：bundle=分层插件（装完自动进 bundles 层并生效）；客户端=带 web 界面组件的插件（通常同时是 bundle，显示 bundle·客户端）；依赖=未声明 dsh.bundle 的普通包，不会挂载。
常见情况：pnpm 拦截依赖构建脚本（如 node-pty）或 git 的 prepare 脚本 → 点黄色提示条的「放行并重装」（等价官方 pnpm approve-builds --all）；装/卸/更新后引擎自动重启；「客户端」插件有新版本时，应用启动后会自动标出可更新并显示更新按钮。
插件安装目录：$DSH_HOME/profiles/web（macOS 默认 ~/.dsh/profiles/web，与命令行 dsh 完全共享）。 

    
安装/卸载/更新后会自动重启引擎。本地目录请填绝对路径（file: 链接）；pnpm 拦截依赖构建脚本（如 node-pty）或 git 的 prepare 脚本时，点「放行并重装」即可（等价官方 pnpm approve-builds --all 流程）。想开发/新建本地插件，到「开发调试」页签。

  


  

    

      
开发调试

      
      这些功能面向开发：新建/调试插件、切换引擎来源、开引擎调试端口，以及日志/配置树/补丁工具。
    

    

      开发调试帮助（总览，按功能分节）

      · 新建插件：输入小写插件名（字母/数字/连字符）→ 点「新建插件」，会在 $DSH_HOME/plugins-local/<名字>/ 生成最小可用的 bundle 插件模板（package.json 声明 dsh.bundle patch 层 + lib/index.js 宿主入口 + cordis.patch.yml），并自动 file: 安装到 profile、重启引擎。改 lib/index.js 后点「重新加载引擎」即可看到改动；模板三件套逐行讲解与客户端插件（dsh.client）开发见 docs/dsh插件开发.md。

      · 引擎来源（开发模式）：把引擎换成你自己构建的 deepseek-harness 源码。填入 checkout 绝对路径 → 保存 → 重新加载引擎生效。优先级：DSH_ENGINE_BIN 环境变量 → resources/engine 打包引擎 → DSH_CHECKOUT 环境变量 → 此处保存的路径。

      · 引擎调试端口：勾选并填端口（默认 9229）。保存后引擎以 NODE_OPTIONS=--inspect=<port> 启动（需重新加载引擎），用 Chrome 打开 chrome://inspect 即可对引擎断点调试；取消勾选即关闭。

      · 引擎日志（实时）：引擎 stdout/stderr 实时流 + 最近 500 行回放，可清空/导出——排查启动失败、看插件 [xxx] mounted 挂载日志都在这里。

      · 配置树（--dump-config）：打印各 bundle + patch 分层叠加后的最终配置树；diff 与上次对比——检查你的 patch 行是否生效/被覆盖用。

      · 补丁文件（cordis.patch.yml）：直接编辑 profile 级或 home 级 patch 层。纯配置改动由 HMR 热生效；增删行属结构性改动，保存会提示重启引擎。
